# Day 4 – Software Testing & QA Fundamentals

## Goal

Learn the fundamentals of software testing and understand the basic QA
process used in software development.

---

## What I Learned

### 1. Software Testing

Software testing is the process of checking whether an application
behaves as expected and identifying defects.

### 2. QA

QA stands for Quality Assurance. It focuses on software quality,
testing processes, and preventing defects.

### 3. SDLC

SDLC stands for Software Development Life Cycle.

Basic flow:

Requirements → Design → Development → Testing → Deployment → Maintenance

### 4. STLC

STLC stands for Software Testing Life Cycle.

Basic flow:

Requirement Analysis → Test Planning → Test Case Design →
Test Execution → Defect Reporting → Test Closure

### 5. Test Scenario

A test scenario describes what needs to be tested.

Example:

> Verify that a user can log in successfully.

### 6. Test Case

A test case contains detailed steps, test data, expected results,
actual results, and test status.

### 7. Functional Testing

Checks whether a feature performs its intended function.

### 8. Positive Testing

Tests the application using valid and expected input.

### 9. Negative Testing

Tests the application using invalid, unexpected, or incorrect input.

### 10. Regression Testing

Checks that existing functionality still works after changes are made
to the application.

### 11. Retesting

Tests a specific defect again after the developer fixes it.

### 12. Integration Testing

Checks whether different components of an application work correctly
together.

### 13. API Testing

Tests backend APIs directly by checking requests, responses,
status codes, and data.

Tools such as Postman can be used for API testing.

### 14. Defect / Bug

A defect occurs when the actual result is different from the expected
result.

### 15. Defect Reporting

A defect report normally includes:

- Title
- Environment
- Steps to reproduce
- Expected result
- Actual result
- Severity
- Priority
- Evidence such as screenshots or logs

### 16. Severity vs Priority

Severity describes the impact of a defect.

Priority describes how urgently the defect should be fixed.

### 17. Smoke Testing

A quick check to determine whether a build is stable enough for
further testing.

### 18. Sanity Testing

A focused check performed after a small change or fix to verify that
the affected functionality works.

## Key Takeaways

- QA focuses on software quality.
- Testing checks whether software behaves as expected.
- SDLC covers the overall software development process.
- STLC focuses specifically on the testing process.
- Test scenarios describe what to test.
- Test cases describe how to test.
- Functional testing checks feature behavior.
- Positive testing uses valid input.
- Negative testing uses invalid or unexpected input.
- Regression testing checks existing functionality after changes.
- Retesting verifies a specific defect fix.
- API testing validates backend APIs.
- Defects should be documented clearly.
- Severity and priority describe different aspects of a defect.
